## understanding the debugger

stops the programing from continuing to run when using the debugger. 
you use breakpoints when you need to understand why a piece of code is failing by using the built in functions described more later.

on the side of your screen, you will see suggested breakpoints and any breakpoints already selected

### debugging bar 

 when debugging, a bar will appear on the top near the file tabs, there are six buttons:
 
 - the two lines pauses the program or if it shows a line and triangle it'll resume the program.
 - the dot with the arrow going over it in a half circle (step over) runs to the next line of code and stops.
 - the dot with the arrow pointing down to it (step into) will run to the next line of code that's ran. so if its calling a function from another file, the debugger brings you to that function.
 - the dot with the arrow pointing up away from it (step out) runs the rest of a function and returns to the code that called it.
 - the green arrow that goes in a circle restarts the program.
 - the red square stops the program
